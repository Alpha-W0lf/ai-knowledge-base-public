# Security Policy

## Reporting Security Issues

If you discover a potential security vulnerability in this project, please report it responsibly rather than opening a public issue.

- Contact: Reach out via [LinkedIn](https://www.linkedin.com/in/tchacko1/) or via GitHub security advisories.
- Response timeline: Reports will be acknowledged with an initial assessment within 48 hours.

Please include:
- A clear description of the vulnerability and its potential impact
- Reproduction steps or proof of concept
- Affected versions, components, or tools

## Local-First Probing Notes

This repository is built as a **local-first knowledge base** and public portfolio surface. When auditing or probing this project, consider the following architecture and boundaries:

1. **Read-Only MCP Surface**: The default MCP profile exposes only read-only tools (`search`, `discover`, `get_status`, `get_context`) advertising `readOnlyHint=True`. Data mutation tools (`add_channel`, `sync_now`) are gated behind `AI_KB_MCP_PRIVATE=1` and remain unregistered on the public profile.
2. **Local Storage and Embeddings**: LanceDB operates as an embedded database on local disk (`data/lancedb/`). Vector embeddings are generated by the local Ollama instance (`nomic-embed-text` on `localhost:11434`). Default fixture ingestion and retrieval make no outbound network requests.
3. **Synthetic Fixtures Only**: Committed test data consists solely of synthetic fixtures in `fixtures/`. Private corpora, personal channels, and local transcripts are gitignored (`channels.local.json`, `data/raw/`). Public MCP and CLI responses cite `source_id` or URLs rather than host filesystem paths.
4. **Sanitized Public Errors**: Public MCP tool handlers sanitize error messages to avoid disclosing host filesystem paths or local system environments.

## Automated Vulnerability Management

Automated dependency vulnerability scanning and security updates are active and managed via GitHub Dependabot.
