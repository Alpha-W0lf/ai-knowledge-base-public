## Problem Statement

### The Friction

The AI and coding space moves fast. New tools, techniques, and best practices emerge weekly across YouTube channels, podcasts, and blogs. This knowledge is:

- **Scattered** — Spread across dozens of sources with no unified access
- **Ephemeral** — Hard to find that video from 3 weeks ago that explained the technique you need now
- **Not semantically searchable** — YouTube search is keyword-based; you can't ask "what's the best approach for MCP tool design?"
- **Inaccessible to AI agents** — Claude can't reference "what did IndyDevDan say about hooks?" during a coding session

### Current Workarounds

Today's workflow involves:
1. Bookmarking videos to watch later (rarely revisited)
2. Manual note-taking (inconsistent, time-consuming)
3. Re-watching content to find specific techniques
4. Relying on memory for cross-referencing insights

These workarounds don't scale. With 23+ channels publishing regularly, valuable knowledge slips through the cracks.

### Why Existing Tools Don't Solve This

| Tool | Limitation |
|------|-----------|
| YouTube history | Keyword-only, no semantic search, not exposed to AI |
| Notion/Obsidian | Manual ingestion, requires active curation |
| ReadWise | Cloud-dependent, subscription, limited to highlights |
| General search | Doesn't have the specific practitioner knowledge |

### Frequency

- **Daily:** Miss connections between related concepts across channels
- **Weekly:** Re-search for content I know I've seen but can't find
- **Per project:** AI assistant lacks context I know exists in my knowledge sources

## Solution Overview

### What We're Building

A **personal, local-first AI knowledge base** that:

1. **Automatically aggregates content** from curated sources
   - YouTube transcripts (primary, 23+ channels)
   - Article/blog inbox (Phase 2)
   - Extensible to podcasts, papers, RSS

2. **Makes it semantically searchable** via embeddings
   - "Claude Code hooks best practices" → relevant transcript snippets
   - Cross-topic queries work naturally
   - Tags for focused filtering when needed

3. **Exposes it to AI agents** via MCP
   - Claude can reference domain knowledge during coding
   - Answers grounded in real practitioner advice
   - Context-aware assistance

### How I'll Actually Use This

**Primary Use Cases:**

1. **AI-Assisted Development**
   - During coding, Claude queries the knowledge base for relevant context
   - "How should I structure this MCP server?" → synthesizes from multiple channels
   - Answers grounded in practitioner experience, not just documentation

2. **Cross-Project Research**
   - `simple_content_platform` queries for video research context
   - Future projects can tap into aggregated knowledge
   - Python SDK for direct integration

**Secondary Use Cases:**

3. **Manual Search**
   - CLI search when I remember seeing something specific
   - Discovery commands to see what's new

4. **Staying Current**
   - Digest of recent content across channels
   - Awareness of trending topics

### Phased Delivery

| Phase | Scope | Outcome |
|-------|-------|---------|
| **V1** | YouTube channel sync + semantic search + MCP | Core value: AI-assisted dev works |
| **V2** | Inbox pattern (drop articles/URLs) | Broader content ingestion |
| **Future** | Multi-topic expansion, podcasts, RSS | Full "second brain" vision |

## Design Principles

These principles guide every design decision:

### 1. Unix Philosophy
- **Do one thing well** — Each module has single responsibility
- **Composable** — CLI pipes, SDK imports, MCP tools work together
- **Text as interface** — Markdown files, JSON state, simple formats

### 2. Local-First
- **No cloud dependencies** — All data on your machine
- **No API keys that expire** — Ollama for inference, no subscriptions
- **Portable** — Clone repo, sync works on any Mac

### 3. Zero-Maintenance
- **Build once, runs forever** — Cron/launchd for automation
- **Self-healing** — Retry logic, graceful degradation
- **No manual intervention** — Daily sync just works

### 4. FOSS Stack
- **Open source only** — No vendor lock-in
- **Swappable components** — Abstract interfaces for future upgrades
- **Community-proven tools** — LanceDB, Ollama, Click

### 5. Simplicity Over Cleverness
- **Obvious structure** — Easy to understand, easy to modify
- **No premature optimization** — Start simple, optimize when needed
- **Tags + embeddings** — No explicit domain field; semantic clustering handles organization naturally

### 6. Resilient Operations
- **Idempotent** — Safe to re-run any operation
- **Partial failure tolerant** — One channel failing doesn't break sync
- **Filesystem as truth** — Can always rebuild state from files

## Non-Goals

Explicit scope boundaries to prevent feature creep:

### Not Building

- **Video player** — We only care about transcripts, not playback
- **Real-time sync** — Daily is fine; streaming adds complexity for no value
- **Multi-user** — Personal knowledge base; no auth, no sharing
- **Recommendation engine** — You curate the channels; no algorithmic suggestions
- **Cloud deployment** — Runs on your laptop, not Kubernetes
- **Web UI** — CLI + MCP are sufficient; HTTP API only if needed later
- **Mobile app** — Desktop/laptop use case only

### Not Optimizing For

- **Massive scale** — Target is 10K documents, not millions
- **Multi-language** — English content only
- **Real-time updates** — Daily sync is the cadence
- **Perfect accuracy** — 90% good enough; edge cases acceptable

### Explicit Tradeoffs

| We Choose | Over |
|-----------|------|
| Simplicity | Feature completeness |
| Local-first | Cloud convenience |
| Reliability | Speed |
| Maintainability | Cleverness |
| Working now | Perfect later |

## Technical Approach

> **Principle:** Vision stays high-level. See `architecture.md` for detailed specifications.

### Stack Overview

| Layer | Choice | Why |
|-------|--------|-----|
| **Vector DB** | LanceDB | Embedded, no server, fast, local-first |
| **Embeddings** | Ollama + mxbai-embed-large | 1024d, local, free, quality |
| **LLM (extraction)** | Qwen3-4B | Sweet spot for metadata extraction on M2 Pro |
| **Language** | Python 3.11+ | Ecosystem, simplicity |
| **CLI** | Click + Rich | Nice UX, minimal complexity |

### Organization Strategy

**Tags + Embeddings Only** (no explicit domain field)

- **Tags:** Topic labels like `["transformers", "mcp", "python"]`
- **Embeddings:** 1024-dimensional vectors for semantic similarity
- **No domain field:** Simpler schema, zero classification errors, embeddings cluster naturally

If coarse filtering is ever needed, derive it from tags at query time.

### Interface Layers

| Interface | Priority | Use Case |
|-----------|----------|----------|
| **CLI** | P0 | Debug, scripts, manual operations |
| **MCP Server** | P1 | Claude Code integration |
| **Python SDK** | P0 | Cross-project integration |
| **HTTP API** | Deferred | Future: web UI, non-Python apps |

All interfaces are thin wrappers (~100 LOC each) around the same core library.

### Hardware Target

- **Primary:** Apple Silicon Mac (M1/M2/M3)
- **Memory:** 16GB unified memory (your M2 Pro)
- **Storage:** 500GB SSD (ample for 10K+ documents)
- **No GPU required:** Ollama runs efficiently on Apple Silicon

## Summary

**AI Knowledge Base** solves the problem of scattered, unsearchable, AI-inaccessible practitioner knowledge by building a local-first system that:

1. **Aggregates** content automatically from curated sources
2. **Searches** semantically via embeddings
3. **Exposes** to AI agents via MCP for context-aware development

**Design philosophy:** Unix principles, local-first, zero-maintenance, FOSS, simplicity.

**Success:** AI agent integration works, powers other apps, runs unattended.

**Non-goals:** Cloud, multi-user, real-time, web UI.
